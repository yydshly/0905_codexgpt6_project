# 我的工程与保存版本

本轮分支 `codex/project-library`，基线 `ffc03aa`。新能力独立增量加入，原布置、短片、作品入口、模型和网站包导出继续保留。

## 启动与使用

```bash
git switch codex/project-library
npm ci
npm run dev
```

打开 http://127.0.0.1:5173/?workspace=projects ，或从布置、短片和作者作品预览右上角点击「我的工程」。`npm run build`、`npm run preview` 用于生产构建检查；后者端口 4173。原默认路由仍是短片，不会强行覆盖之前的入口。

- **新建工程**：输入名称，从已布置的书房开始，自动保存初始版本。
- **继续编辑**：每张卡片都有「继续布置」「镜头短片」「作品展示」。三者始终打开这张卡片的同一套工程；名称、家具、作品绑定和镜头分别隔离。
- **另存为新工程**：编辑器右上「我的工程」里输入名称。复制当前已保存或未保存的内容，生成独立工程，原工程不变。
- **复制工程**：在工程库复制某套已保存工程，副本从版本 1 开始，不复制原工程的历史。
- **保存并切换**：「保存并返回工程库」保存成功后才离开。数据库失败或并发冲突时保留当前画面，可继续编辑、备份或另存为。
- **保存版本**：有内容变化的保存会追加一个版本；只选择物件、移动播放头或重复保存相同内容不会增加版本。恢复会追加新版本，恢复前的所有保存版本继续保留。
- **备份与导入**：卡片「备份 JSON」导出当前完整工程；「导入 JSON 为新工程」创建独立副本，不替换其他工程。JSON 不携带整个历史版本库。
- **发布**：打开某张卡片的作品展示 → 发布展示页 → 下载网站 ZIP。包中只含该工程当前的公开内容，其他工程和历史版本不进入发布包。

## 旧存档与存储方式

首次进入工程库，读取当前浏览器原房间和短片存档，各自迁入独立工程，原始 localStorage 字节不修改。相同内容不会重复迁入；快速工作区以后保存了不同内容，再进入工程库时会作为新工程保留，避免覆盖已经继续编辑的迁入工程。旧房间/短片解析沿用原版本迁移规则，例如最早版本的固定墙画会转换为可编辑相框。

没有 `id` 的旧入口是「快速工作区」，保留原本房间与短片各一个存档槽的兼容行为。管理多套方案请通过工程库进入。正式工程链接使用 `?workspace=room|film|portfolio&id=…`；刷新继续读取同一个 ID。这个 ID 是本地标识，不能作为跨设备分享网址。

IndexedDB 数据库 `ideal-study.projects`，结构版本 1：

- `projects`：当前工程快照、独立 ID、保存版本号、创建/更新时间、真实场景缩略图。
- `versions`：按 `[projectId, revision]` 存储完整保存快照，带恢复/创建/保存来源说明。
- `meta`：原房间/短片存档的迁入标记与内容签名，用于去重。

当前工程与版本写入使用同一数据库事务，事务失败两者一起回滚。保存和恢复检查读取时的版本号；另一标签页已保存时拒绝静默覆盖，用户可另存为保留分支。缩略图单独更新，不增加内容版本；无 WebGL 时显示预览不可用，工程库仍能管理数据。

每个工程为原短片 v4（内含房间 v3、作品配置 v2），没有另造展示专用场景。单个 JSON 上限仍为 6 MB，原物件/镜头/作品限制不变。没有新增包依赖，也没有外部图片或模型资产。

## 边界

工程与版本仅保存在当前浏览器、当前网站地址下。不同端口/域名不共用数据库；清除网站数据、隐私模式结束或浏览器回收存储可能使数据丢失，重要内容请下载 JSON 备份。版本没有自动删除策略，空间耗尽时明确报告失败；不会为了释放空间删除用户工程。

本轮没有账号、云同步、自动公网发布、整库历史备份、工程删除/回收站、跨设备工程共享或历史版本差异对照。恢复针对已保存版本；每次拖动的撤销栈仍属于当前编辑会话，刷新不会恢复它。JSON 导入/发布仍复用此前机制。

真实手机 GPU、Safari/Firefox、数百套工程和超大版本库的性能尚未验证。桌面编辑与窄屏工程管理的实测范围见 [PROJECTS-VALIDATION.md](PROJECTS-VALIDATION.md)。
