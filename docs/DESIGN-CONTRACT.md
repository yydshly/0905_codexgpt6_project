# 理想书房 · 交付约定

- 入口：完整产品 brief；直接实施，三个阶段连续推进。
- 用户：桌面浏览器用户，布置一间可保存和导出的创作书房。
- 视觉目标：Immersive / Spatial Stage。暖橡木、浅墙、深金属、亚麻与植物；默认有完整构图。
- 场景：Three.js WebGL，固定 5.2 × 4.4 m 单房间，8 类可编辑物件；几何和材质在项目中自行制作。
- 界面：中央持续可见的 3D；左物件缩略图库；右属性/引导；顶名称和文件操作；底真实光照预设。
- 状态映射：选择有轻量轮廓/地面标记；材质/灯光即时更新；未选中显示空间信息和教程；失败保留数据。
- 编辑边界：水平位置吸附 0.1 m、朝向 15°快捷旋转，房间边界限制，桌面物件支撑关系；不做物理或 CAD。
- 主流程：默认 → 加台灯 → 移动旋转 → 灯光/家具材质 → 深夜 → 撤销重做 → 本地保存 → 刷新恢复 → PNG → JSON 导入导出一致。
- 镜头：物件编辑和观察模式明确区分；默认/近景/俯视；旋转与缩放。
- 环境：Windows，本地 Node 22，Chromium；重点 1440×900、1280×800。窄屏提供面板抽屉，完整手机编辑不在验收范围。
- 降级：WebGL 不可用时显示故障说明，仍可导出/导入方案数据。
- 用户授权：自行决定可逆技术细节、创建源码、运行测试、按已配置 GitHub 提交记录。新增收费、删除用户数据或扩大权限须确认。
- 阶段一：场景/完整 UI，实际浏览器检查默认、近景和俯视。
- 阶段二：真实编辑与文件闭环。
- 阶段三：多尺寸、多角度、状态/历史/恢复/性能回归与修正。
- 交付：源码、README、至少三张真实截图、验证记录、环境/性能/问题清单、GitHub 提交。

## 第二轮优化约定（2026-09-05）

- 入口：用户「继续优化」。保留已交付的布局、八类物件、v1 本地方案格式与操作闭环。
- 实际基线：Chrome 1440×900 默认/近景；椅背仍近似平板，植物叶片近似厚圆片；选中反馈偏细，手动镜头变化与预设按钮状态不一致。重复键帽、毯穗、地板独立提交绘制。

- 验证：真实浏览器复查默认/近景/俯视/深夜、1440×900 与 1280×800；回归原完整验收流程；补充实例化后的拾取/删除撤销、镜头按钮/保存恢复、选择标记与模式反馈。重新测量绘制次数、帧时与空闲绘制。
- 输出：更新实际截图及机器记录、优化报告、GitHub 提交和 CI 结果。没有浏览器证据的内容不标记完成。
