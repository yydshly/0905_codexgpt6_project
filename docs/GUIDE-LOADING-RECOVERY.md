# 角色切换、快照恢复与配置入口 · 2026-09-06

## 问题与实际观察

用户报告在线导览切换角色后打不开。原内置浏览器标签确实显示 `This page crashed`。重新打开同一 HTTPS 地址的标签后来正常显示导览，但没有该快照的本地数据，显示示例提示。独立 Chrome 的线上检查完成四种角色间五次切换、保存与刷新，未复现页面崩溃。

因此，不能把“切换必然崩溃”作为已确认结论，也不能把以下加固称作已根治原标签页的浏览器进程崩溃。尚未读取或修改用户崩溃标签中的原工程，无法确认其选中角色和本地数据。

已确认的代码问题：

- 模型下载及解析没有时间上限，切换期间整个编辑面板被禁用，网络长时间不返回时无法取消。
- 首次角色失败后没有重试按钮，也不能改选一个可以加载的角色。
- 角色移除时没有释放骨骼纹理、关闭解码位图；异常路径也未完整清理模型资源。
- 恢复导览前先解析标签传递的房间来源，损坏来源会阻断有效本地导览存档的读取。
- 配置面板位于侧栏下方，首屏不易发现。

## 本次修正

1. 下载以连续 30 秒无进展为超时，流式显示已收到的 MB 数；解析阶段限时 30 秒，单文件整体上限 2 分钟。提供取消、失败重试。尚未替换成功时保留原角色、工程和历史。
2. 首次失败后支持重试原角色或改选角色，保留 JSON 备份和保存能力。未完成的加载在离开页面时取消；取消后晚到的解码结果也会释放。
3. 释放角色专属几何体、材质、纹理、共享骨骼和位图，包含失败路径；房间的共享资源不受影响。
4. 先读取有效已保存导览，再回退到房间来源。来源或存档损坏时明确提示并保留原始内容，没有自动删除或覆盖。
5. 顶部增加“配置角色”，直接定位并聚焦既有设置区，解释独立导览与房间工程的关系。

## 目前配置能力的准确边界

角色仍属于独立导览工作区。可选四种已接入形象，调整名字、上衣配色、段落时长／顺序与坐下使用的椅子；鸣人可选择自然行走或忍者跑。角色及动作使用同一份导览数据进行预览、时间轴采样、视频和独立网站导出。

房间工程 → 包含房间与作品的独立导览快照 → 保存导览／导览 JSON／视频／网站包。

角色目前不是房间物件列表里的可拖动物件，不支持任意模型上传、在房间编辑器设置角色位置、自由编辑动作路径，也不会把角色设置自动写回原房间工程。“我的工程”的房间版本管理尚未统一管理这份独立导览。

`snapshot=...` 是本地存储索引，不是服务器分享 ID。首次来源在当前标签的 sessionStorage；点击保存后导览才写入同一站点的 localStorage。仅复制地址不能跨设备带走数据；跨设备编辑应使用导览 JSON，公开展示应部署导出的网站包。先前导出到别处的网站需要重新导出、重新部署才包含本次修正。

## 剩余限制

原内置浏览器标签的崩溃根因仍未确定。JavaScript 超时和重试可以处理资源加载失败，无法在浏览器渲染进程已经退出后自行恢复该进程。未验证 Safari、Firefox、真实手机，以及低内存情况下的全部角色组合。此次没有更改模型精度、动作表现或导出分辨率，也没有把角色模块改造为统一房间编辑器。
